# v4.5 — Trustworthy Context

**Status:** planned — next release
**Predecessor:** [v4.4.5](../../CHANGELOG.md) (shipped 2026-05-30)
**DoD entries:** `docs/release/v4-outcomes.yaml` — `v4.5-index-hygiene`, `v4.5-graph-own-code`, `v4.5-e2e-tokens`, `v4.5-docs-current`

---

## 1. Why v4.5

v4.4 shipped symbol enrichment (symbol_body field), six new language analyzers, and a honesty-framed benchmark comparison (v4.4.4). What it did not fix — and the evidence below confirms — is that the index itself is polluted by vendored code, the graph shows the wrong symbols entirely, token-saving claims measure packs not agent sessions, and the docs still cite a stale version. A user who installs v4.4.5 and runs `context-router graph` sees a dependency graph of dnspython and docutils, not their own code. That is a correctness failure, not a missing feature.

v4.5 is the "trustworthy context" release: before adding anything new, make what we already ship actually work as advertised.

---

## 2. Evidence baseline (2026-06-09)

The following facts were confirmed against the live `develop` branch on 2026-06-09 and motivate every workstream below.

### 2.1 Index pollution

The index of this repo contained **48,970 symbols**, of which **44,661 (91%) came from `.venv-crg/` site-packages**, because `ignore_patterns` in `packages/contracts/src/contracts/config.py:78` defaults to the literal `.venv` only — no `.venv-*` glob, no `node_modules`, no gitignore awareness. A virtualenv named `.venv-crg` passes the filter unchanged.

### 2.2 Graph shows zero own-code symbols

`context-router graph` rendered **500 nodes / 1,466 edges with zero symbols from `packages/` or `apps/`** — every node was vendored (dnspython / docutils / fastmcp / jwt). Root cause: `SymbolRepository.get_all(repo, limit=10_000)` (`packages/storage-sqlite/src/storage_sqlite/repositories.py:537`) returns an unordered 10 K slice of the polluted index; top-500-by-degree selection keeps only vendored symbols because they have far more intra-package edges.

### 2.3 Silent no-op on `--json -o`

`graph --json -o file.json` silently ignores the `-o` flag. No file is written and no warning is emitted. This violates quality-gate rule 2 ("no silent failures").

### 2.4 Retrieval quality regressed and was not re-baselined

Judge benchmark history: **v4.3 F1 = 0.394** vs **v3.3.0 F1 = 0.577**. Phase C of `docs/superpowers/plans/2026-04-25-v4.4-roadmap.md` (retrieval quality improvements) never shipped. Phases A (evaluation/downstream.py) and B (symbol_body field + orchestrator wiring) have landed but Phase C was skipped without a re-baselining note.

### 2.5 Benchmark methodology gap

Benchmark claims count **pack-pointer tokens**, not end-to-end agent tokens. The headline n=3 k8s comparison (406 vs 3,478 tokens) measures what context-router hands to the agent, not what the agent then reads. A real session includes downstream file reads; those are uncounted.

### 2.6 Docs staleness

README claims version **v4.4.3** and the standalone headline "**91% fewer tokens**"; the current release is **v4.4.5**; the honest v4.4.4 framing (workload-matched comparison) is **~88%**. `docs/roadmap.md` does not yet reference v4.5.

## 3. Non-goals

- **No new MCP tools.** The four existing retrieval tools are sufficient; a fifth would only add surface without fixing correctness.
- **No new language analyzers.** v4.4 added six; the bottleneck is index quality, not language coverage.
- **No hook / passive-interception mode.** Watching editor events for automatic index updates is a v4.6 candidate; it is excluded here to keep the scope narrow.
- **No breaking changes** to `ContextItem`, `MemoryHit`, or any MCP tool signatures.

## 4. Workstreams

### Workstream 1 — Index hygiene

**Outcome:** The indexer never ingests vendored or generated code. Defaults cover the common cases; `.gitignore` is honoured when present.

**Scope:**
- Expand `ignore_patterns` default in `packages/contracts/src/contracts/config.py` to include: `.venv*`, `venv`, `env`, `.env*`, `node_modules`, `vendor`, `dist`, `build`, `target`, `__pycache__`, `.git`, `.hg`, `*.egg-info`, `.tox`, `cache`, `.cache`.
- Implement gitignore-aware directory pruning in the scanner: read `.gitignore` at repo root; translate glob patterns to directory exclusions; warn to stderr if `.gitignore` is unreadable (OS reason named), then proceed with built-in patterns.
- Add `context-router doctor` check: after indexing, emit a structured warning if any `file_path` in `symbols` matches an ignore pattern (catches stale pre-hygiene indexes).
- Index-time prune: on incremental `index` runs, DELETE rows whose `file_path` matches ignore patterns before scanning new files.

**DoD:** `v4.5-index-hygiene` (see `docs/release/v4-outcomes.yaml`).

---

### Workstream 2 — Graph trustworthiness

**Outcome:** `context-router graph` renders the user's own code. `graph --json -o <file>` writes the file. A stale polluted index causes a named warning, not a silent vendored graph.

**Scope:**
- In `SymbolRepository.get_all`, add an `order_by` clause (e.g. `ORDER BY file_path`) and emit a loud stderr warning when the result is capped: `WARN: symbol query capped at N — some symbols omitted; re-run 'context-router index' to see full graph`.
- Add ignored-path filter to graph node selection: after fetching symbols, drop any node whose `file_path` matches the current ignore patterns; if dropped count > 0, emit `WARN: dropped N symbols from ignored paths — re-run 'context-router index'`.
- Fix `graph --json -o <file>`: write the JSON to `<file>` when `-o` is supplied; emit `INFO: graph written to <file>` on stderr. If `-o` is absent, write to stdout as before. A missing parent directory is an error (exit 1, named message).

**DoD:** `v4.5-graph-own-code` (see `docs/release/v4-outcomes.yaml`).

---

### Workstream 3 — End-to-end token benchmark

**Outcome:** Token-saving claims are end-to-end: pack tokens + downstream file-read tokens, with a model-judge sufficiency check, across n ≥ 12 holdout tasks.

**Scope:**
- Extend `benchmarks/judge_packs.py` (from Phase A) to record `downstream_read_tokens` per task: count tokens for every file the agent reads after receiving the pack.
- Add a model-judge step using `claude` CLI (claude-fable-5 / claude-sonnet-4-6 as available): for each task, ask "did the pack contain enough context to complete the task? yes/no + one-sentence reason". Record as `judge.sufficient` and `judge.reason`.
- Run on n ≥ 12 holdout tasks across ≥ 4 repos (must include at least one repo not in the training set of any prior benchmark).
- Update `BENCHMARKS.md` headline to report end-to-end tokens (pack + downstream), model-judge sufficiency rate, and task count. Remove or demote the pack-only figure.
- Guard: if `claude` CLI is absent, `judge_packs.py` exits 1 with `ERROR: claude CLI not found — judge step requires it` on stderr; never writes a results file with empty judgements.

**DoD:** `v4.5-e2e-tokens` (see `docs/release/v4-outcomes.yaml`).

---

### Workstream 4 — Retrieval quality re-baseline + docs currency

**Outcome:** Phase C of the v4.4 roadmap (retrieval quality improvements) ships, re-baselined against a clean index. User-facing docs state the correct version and honest benchmark framing.

**Scope (retrieval quality):**
- Re-run the v4.3 judge benchmark against a clean (post-hygiene) index. Establish a new F1 baseline.
- Implement at least one Phase C improvement from `docs/superpowers/plans/2026-04-25-v4.4-roadmap.md` that raises F1 above the v3.3.0 baseline (0.577). Record the result in `docs/benchmarks/`.
- If F1 does not improve after hygiene, document the gap as a risk in this file and carry it to v4.6.

**Scope (docs currency):**
- README: update version to v4.4.5, replace standalone "91% fewer tokens" headline with workload-matched "~88% fewer tokens (workload-matched, n=3)" and link to `BENCHMARKS.md`.
- `docs/roadmap.md`: add v4.5 section header with status "in progress".
- `.handover/` docs: sweep for any v4.3 / v4.4.3 references; update to current.
- CHANGELOG: add v4.5 section stub.

**DoD:** `v4.5-docs-current` (see `docs/release/v4-outcomes.yaml`).

## 5. ADRs / key decisions

| Decision | Rationale |
|---|---|
| Expand built-in ignore defaults rather than requiring config | Users should not have to configure `.venv-*` exclusion; safe defaults prevent the most common case of virtualenv pollution. |
| Gitignore integration uses root `.gitignore` only (no nested) | Nested `.gitignore` files require recursive descent and make prune semantics complex. Root-only covers 95% of cases. Nested is v4.6 scope. |
| Graph ordered `get_all` with cap warning (not silent truncation) | Complies with quality-gate rule 2; gives users actionable feedback. |
| End-to-end benchmark uses model judge (claude-fable-5) | Pack-pointer tokens alone do not measure whether context was sufficient. A judge adds a sufficiency signal without requiring a human grader. |
| Docs update is a P1 workstream, not an afterthought | Wrong version numbers and inflated benchmark claims erode user trust more than missing features. Treating it as a first-class workstream ensures it ships. |

## 6. Risks

| Risk | Likelihood | Mitigation |
|---|---|---|
| Gitignore parsing edge cases (negation, `**` globs) cause false exclusions | Medium | Conservative implementation: only handle the common patterns; log a warning for unrecognised syntax and skip that line. |
| Hygiene-only F1 gain is negative (clean index finds fewer symbols, hurting recall) | Low–Medium | Re-run benchmark immediately after hygiene; if F1 drops, pause Phase C and investigate before shipping. |
| Model judge rate-limits or is unavailable during CI | Medium | Judge step is a separate `make bench-judge` target, not in the default CI gate; CI only runs the structural verify (results JSON schema check). |
| Docs sweep misses a stale reference | Low | Verify step uses `grep` to assert no "4.4.3" or standalone "91%" remain in README; reviewer checks diff. |
