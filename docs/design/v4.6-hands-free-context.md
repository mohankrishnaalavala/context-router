> Status: APPROVED 2026-06-10. Scope = Phase A (graph accuracy) + Phase B
> (auto-fresh index) from `docs/superpowers/plans/2026-06-10-v4.6-roadmap.md`.
> Phase C (auto-save observations) + Phase D (savings dashboard) are split
> into **v4.7.0** and are NOT in this release.
> DoD entries: `docs/release/v4-outcomes.yaml` ids `v4.6-*`.
> Implementation plan: `docs/superpowers/plans/2026-06-10-v4.6-implementation.md`.

## Why

v4.5 made context trustworthy at pack time. Two gaps remain, both proven on
the pydantic real-world validation (`benchmarks/realworld-pydantic-13215.md`):

1. **The graph stores wrong data.** 37.6% of pydantic's edge rows are
   duplicates (9,110 redundant rows; worst case 161 identical
   `extends → BaseModel` rows from one test file), the reported edge count
   disagrees with the DB, and on >10k-symbol repos the internal pipeline
   silently ranks over a partial symbol slice.
2. **Freshness requires a ritual.** The index only updates via manual
   `context-router index` or a foreground `context-router watch` daemon.
   Competitors auto-index; we make the user remember.

Order is deliberate: fix accuracy before automating refresh — auto-updating a
graph that double-counts edges just refreshes wrong data faster.

## Phase A — Graph accuracy & integrity

### A1. Edge dedup (storage layer)

Migration adds `UNIQUE(repo, from_symbol_id, to_symbol_id, edge_type)` on
`edges` (rebuild table, collapsing existing duplicates; keep max weight).
`EdgeRepository.add_bulk` (`packages/storage-sqlite/src/storage_sqlite/repositories.py:927`)
switches to `INSERT OR IGNORE`. Re-index idempotency via `delete_by_file()`
is unchanged.

**Weight semantics:** today duplicate rows acted as implicit edge weight
(161 rows ≈ weight 161). After dedup, repeated occurrences within one file
batch are collapsed **before** insert with `weight = occurrence count`, so
legitimate "calls X many times" signal survives as weight, not row count.
Degree-based ranking must consume weight, not row multiplicity.

### A2. Qualify same-named local symbols (writer layer)

The edge resolver (`packages/graph-index/src/graph_index/writer.py:107–267`)
collapses symbols by `(file, name)`, so hundreds of `class Model(BaseModel)`
definitions in one pydantic test file become one symbol row while each
definition emits its own edge. Fix: qualify symbol identity with the
enclosing scope (parent symbol chain, e.g. `test_generics.test_foo.Model`);
unqualified display name retained in a separate column/field so retrieval by
short name (`"Model"`) keeps working.

**Risk:** symbol identity churn invalidates `pack_cache` and any stored
symbol references → bump the cache/schema version so old caches are
discarded loudly, not served stale.

### A3. Edge-count reporting consistency

The count printed by `index` must equal `SELECT count(*) FROM edges WHERE
repo = ?` after the run (pydantic showed 24,718 reported / 27,915 on re-run /
24,253 stored). Likely double-count of pre-resolution candidates vs stored
rows. After A1, the reported number is the post-dedup stored number.

### A4. Page internal `get_all` callers

`SymbolRepository.get_all` keeps its 10k cap + loud WARN for external
callers. New `iter_all(repo, batch_size=5000)` generator pages without a cap.
The four internal consumers convert
(`packages/core/src/core/orchestrator.py:1668` candidate assembly, `:1696`
community boost, `:2315` call chain, `:2743` grounding) so ranking covers the
full symbol set on >10k-symbol repos.

### A5. Graph ground-truth accuracy audit

Hand-verify edges for a stratified sample (≥30 symbols across this repo +
the pydantic clone), compute per-edge-type precision/recall, publish
`docs/eval/2026-06-10-v4.6-graph-accuracy.md` — baseline before A1/A2, re-run
after. Decision rule: any edge type with recall < 0.8 post-fix gets a named
finding (fix-in-release or explicitly deferred with rationale).

## Phase B — Auto-fresh index

### B1. Pack-time staleness self-heal

Before assembling a pack, the orchestrator compares stored per-file
fingerprints (mtime + size, recorded at index time) against disk:

- ≤ 25 stale files (config `staleness.max_inline_reindex`): re-index just
  those files inline (reuse the watcher's `delete_by_file()` +
  `index_file()` path), emit `info: re-indexed N stale files` to stderr.
- > 25 stale files: emit `WARN: index is stale (N files changed) — run
  'context-router index'` and proceed with the stale index. Never a silent
  stale pack.
- Disabled (`staleness.check: false`) or fingerprints missing (pre-v4.6
  index): WARN with named reason, behave as today.

Works for every client (CLI + MCP, any agent), no daemon required. The
watcher remains available but becomes an optimisation, not a requirement.

### B2. `context-router hooks install`

New CLI command group (`apps/cli/src/cli/commands/hooks.py`) that writes
Claude Code hook entries into the project's `.claude/settings.json`:

- `PostToolUse` (Edit|Write|MultiEdit) → `context-router update-index --file
  <changed file>` for instant freshness between packs.
- Installer is idempotent (second run = byte-identical file), merges with
  existing user hooks (never clobbers), and `hooks uninstall` removes only
  our entries. Non-project dir → error with named reason.
- v4.7 will extend the same installer with the SessionEnd auto-capture hook;
  the command surface is designed for that (`hooks install [--global]`).

## Non-goals (v4.6.0)

- Auto-save observations, memory health checks → v4.7.0 (Phase C).
- Savings dashboard, pack_events telemetry → v4.7.0 (Phase D).
- Multi-repo/workspace federation — deferred (user decision 2026-06-10).
- New runtime dependencies: none permitted by this spec.
