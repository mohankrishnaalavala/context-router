## Method

1. **Stratified, reproducible sample of 31 symbols** (16 context-router + 15 pydantic), selected purely by SQL with a fixed stride over `ROW_NUMBER() OVER (ORDER BY id)` — no cherry-picking. Selection queries are recorded verbatim below.
2. For each sampled symbol, the source definition was read and its **true outgoing project-internal relationships** were hand-enumerated:
   - `calls`: every direct call in the body whose target is a project-internal function/class, **including** constructor calls (`Foo()`) and method calls whose receiver type is a project class (`self.x()`, `orch.build_pack()`) — these are resolvable by a human reading the code, so missing them counts as a recall miss.
   - `extends`: project-internal (or external) base classes — for class symbols only. Method bodies belong to the separate method symbols the indexer creates, so class symbols' truth sets contain only class-level relationships.
   - `imports`: project-internal imported names actually *used* by the symbol's body or signature (module-level or function-level imports).
   - Skipped from truth: stdlib and third-party targets (incl. `pydantic_core` / `typing_inspection` / `typing_extensions` for pydantic — the vendored `pydantic-core/` directory is in the index, which is itself a source of noise, noted below). Calls through stored function attributes (`self._attempt_rebuild()`) and `__call__` protocols (`handler(int)`) were marked **ambiguous** and excluded from both truth and scoring.
3. Stored outgoing edges were queried per symbol (`JOIN symbols` twice to resolve names), **deduplicated to distinct (from, to, type) triples** for scoring — duplicate rows are measured separately. Stored edges with `<external>` targets were excluded from P/R scoring (the schema intentionally stores them) but are noted.
4. Precision = correct distinct stored edges / all distinct stored project-internal edges. Recall = true edges found / all true edges. Aggregated per type, per repo, combined.
5. Duplicate-row rate and (file, name) symbol-collision counts computed over the full DBs.

## Findings

1. **Imports are the broken edge type — both attribution and resolution.** All of a file's import edges are attached to the *first function symbol in the file* (`_dedup_ranked` carries orchestrator.py's imports; `_check_frozen` carries main.py's; `test_success` carries test_main.py's), giving symbol-level precision of 0.06 combined. On top of that, target resolution is bare-name based: stdlib `json`/`copy`/`hash` resolve to same-named project symbols (`BaseModel.json`, `BaseModel.copy`, a Rust `hash` fn in `pydantic-core/src/url.rs`), and re-exports resolve to the wrong re-exporter (`ValidationError` → `pydantic/v1/error_wrappers.py`). Meanwhile whole import groups are silently absent (none of orchestrator.py's graph_index/ranking/storage_sqlite imports produced edges).
2. **Calls precision is decent (0.82) but recall is poor (0.33), with a systematic shape.** Captured reliably: same-file calls and direct constructor calls (`Orchestrator()`, `Symbol(...)`). Missed almost always: (a) method calls on instances (`orch.build_pack()`, `checker.check()`, `self._type_schema()`, `cls.model_construct()`) — dynamic dispatch is either dropped or, worse, name-resolved into the wrong file (`build_pack` → an unrelated test helper; `Orchestrator().last_pack()` → a self-loop onto the calling CLI function; `super().visit()` → itself); (b) calls behind function-level imports (`PackStore`); (c) module-qualified calls (`_generics.replace_types`, `_typing_extra.annotated_type`) — `__class_getitem__` has 12 internal calls and zero internal edges. The 4 call FPs in the sample are all bare-name collision misresolutions, the exact defect class A1/A2 address.
3. **Extends is correct but massively duplicated.** Every spot-checked distinct extends edge (8/8 pydantic, 23/23 context-router) is real; the defect is volume: 45.7% of pydantic extends rows are redundant copies, driven by same-named local test classes collapsing onto one symbol id at edge-resolution time (161× `Model → BaseModel`). Dedup (A1) + collision-aware identity (A2) should fix this without any recall cost.
4. **Vendored sub-repos pollute resolution.** The pydantic clone's `pydantic-core/` directory (Rust + Python + its own tests/benchmarks) is indexed as project-internal, donating absurd targets (`core_schema` → a benchmarks test file, `hash` → url.rs). Worth a follow-up decision (index-scope exclusion or repo boundary detection) — not covered by A1/A2.
5. **Honest caveats.** Sample is 31 symbols; 12 of them have empty truth sets (vacuous true negatives — they still validate that the graph doesn't fabricate edges for simple symbols, which it doesn't). Method-call truth assumes a human-resolvable receiver type; `self._attempt_rebuild()` (stored callable) and `handler(int)` (`__call__`) were excluded as ambiguous. Class-symbol truth excludes method-body relationships because methods are separate symbols in this schema.

### Decision rule: edge types with recall < 0.8 post-fix

Both scored types are below 0.8 recall. As predicted in the baseline, A1/A2 fixed duplication and identity collapse — they did not (and were not scoped to) fix attribution or resolution:

1. **Imports attached to the first function symbol of the file** (imports P 0.06, R 0.21 — unchanged). `_dedup_ranked`, `_check_frozen`, `test_success` still carry their whole file's import edges. **DEFERRED to v4.7** — requires per-symbol usage attribution, orthogonal to A1/A2's identity/dedup scope.
2. **Stdlib/builtin bare-name misresolution** (counted in imports/calls FP). Stdlib `json`/`copy` still resolve to `BaseModel.json`/`BaseModel.copy`; builtin `hash` still resolves to `pydantic-core/src/url.rs`; `ValidationError` still lands on `v1/error_wrappers.py`. **DEFERRED to v4.7** — needs import-statement-aware resolution with a stdlib/builtin denylist; not a duplication defect.
3. **Call-resolution misses** (calls R 0.35 combined). Method calls on instances (`orch.build_pack()`, `self._type_schema()`, `cls.model_construct()`), module-qualified calls (`_generics.replace_types`), and callees behind function-level imports (`PackStore`) are still dropped or name-misresolved (the `super().visit()` self-loop and `Orchestrator().last_pack()` → CLI fn persist). `BaseModel.__class_getitem__` still has 12 internal calls and zero internal edges. **DEFERRED to v4.7** — requires receiver-type/qualified call resolution; A1/A2 only guaranteed that whatever is resolved is stored once, against the right identity.
