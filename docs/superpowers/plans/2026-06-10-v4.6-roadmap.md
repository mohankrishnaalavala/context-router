# v4.6 Roadmap Plan — "Hands-Free Context"

> Status: APPROVED 2026-06-10 with SPLIT — **v4.6.0 = Phase A + B**
> (spec: `docs/design/v4.6-hands-free-context.md`, DoD ids `v4.6-*`,
> implementation plan: `2026-06-10-v4.6-implementation.md`);
> **v4.7.0 = Phase C + D** (spec/DoD to be written when v4.6.0 ships).

**Goal:** Remove the two manual rituals (start watcher, remember to save
observations), make graph data provably accurate, and make token savings
visible on a local dashboard.

**Theme rationale:** v4.5 made context *trustworthy*; v4.6 makes it
*hands-free*. Every competitor friction-point we identified (claude-mem
auto-captures; CRG auto-indexes) is a ritual we still require.

**Explicit non-goals (deferred):**
- Multi-repo / workspace federation — revisit after v4.6 (user decision 2026-06-10)
- SSE transport (backlog B1), VS Code extension (B7), v5 symbol-ID memory

## Phase A — Graph accuracy & integrity (P0, do first)

Trust before automation: auto-updating a graph that double-counts edges just
refreshes wrong data faster. These are the four findings from the pydantic
real-world validation (`benchmarks/realworld-pydantic-13215.md` §Findings)
plus a formal accuracy audit.

### A1. Edge dedup — unique constraint + INSERT OR IGNORE
- **Where:** `packages/storage-sqlite/src/storage_sqlite/repositories.py:927`
  (`EdgeRepository.add_bulk`) + new migration adding
  `UNIQUE(repo, from_symbol_id, to_symbol_id, edge_type)`.
- **Evidence:** 37.6% of pydantic edges are duplicates (9,110 redundant rows);
  worst case 161 identical `extends → BaseModel` rows from one test file.
  Inflates degree-based ranking toward test files.
- **DoD sketch:** outcome = re-index pydantic produces 0 duplicate
  (from,to,type) rows; threshold = `SELECT count(*) ... GROUP BY ... HAVING
  count(*)>1` returns 0; negative_case = same-named classes in one file still
  produce ≥1 edge each to distinct targets; verify = migration test + pydantic
  fixture re-index.

### A2. Qualify same-named local/nested symbols
- **Where:** `packages/graph-index/src/graph_index/writer.py:107–267`
  (edge resolver) — symbol identity currently collapses `(file, name)` so
  hundreds of `class Model(BaseModel)` in one test file become one symbol.
- **Fix:** qualify nested symbol names with enclosing scope
  (`test_foo.Model@L42` or parent-qualified name) so distinct definitions get
  distinct rows; edges then dedup naturally.
- **Risk:** symbol-ID churn invalidates `pack_cache` and any stored
  references — needs a cache-bust migration note. Call this out in the spec.

### A3. Edge-count reporting consistency
- **Where:** index summary printing vs `edges` table truth. Pydantic: first
  run reports 24,718, later runs 27,915, DB holds 24,253.
- **DoD sketch:** reported count == `SELECT count(*) FROM edges WHERE repo=?`
  after every run, including incremental watch updates.

### A4. Page internal `get_all` callers past the 10k cap
- **Where:** `packages/storage-sqlite/src/storage_sqlite/repositories.py:538`
  (`SymbolRepository.get_all`, hard 10k LIMIT) and its four internal callers:
  `orchestrator.py:1668` (candidate assembly), `:1696` (community boost),
  `:2315` (call chain), `:2743` (grounding).
- **Fix:** add `iter_all(repo, batch_size=5000)` generator; convert internal
  callers; keep the loud WARN for *external* `get_all` consumers.
- **DoD sketch:** negative_case = pydantic (15,623 symbols) pack run emits no
  partial-slice WARN from internal pipeline; ranking pool covers all symbols.

### A5. Graph ground-truth accuracy audit (answers "is it connecting properly?")
- What we know today: edge *types* work end-to-end (validated by rank 3/37 on
  pydantic issue #13215; 17,570 calls / 4,082 extends / 2,446 imports /
  145 tested_by / 10 depends_on edges), but precision/recall of edges has
  never been formally measured — only retrieval F1 has.
- **Task:** sample ~30 symbols across 2 fixture repos (one Python, one TS),
  hand-enumerate their true outgoing edges from source, compare to DB.
  Publish `docs/eval/<date>-v4.6-graph-accuracy.md` with per-edge-type
  precision/recall. Run once before A1/A2 (baseline) and once after (proof of
  improvement).
- **Gate:** if recall for any edge type < 0.8, fixing that resolver enters
  Phase A scope.

## Phase B — Auto-fresh index (no manual watcher)

Two layers, shipped together; layer 1 works with *every* agent, layer 2 makes
it instant for Claude Code users.

### B1. Pack-time staleness check + incremental self-heal
- **Where:** `packages/core/src/core/orchestrator.py` pack entry; reuse the
  per-file incremental machinery from `apps/cli/.../watcher.py`
  (`delete_by_file()` + `index_file()`).
- **Behavior:** before assembling a pack, compare mtimes of indexed files
  (cheap: store `indexed_at`/content hash per file) against disk; re-index
  only changed files inline when the count is small (≤ N, default 25); emit
  `info: re-indexed 3 stale files` to stderr; above N, WARN and suggest
  `context-router index`.
- **Why this design:** no daemon, no hook dependency, works under MCP for any
  client (Cursor, Copilot, Claude Code). The watcher becomes optional, not
  required.
- **DoD sketch:** outcome = edit a file, run `pack` without `index`, the
  edited symbol appears with fresh line numbers; negative_case = >N stale
  files triggers named WARN, never a silent partial pack.

### B2. `context-router hooks install` (Claude Code integration)
- **New command:** `apps/cli/src/cli/commands/hooks.py`, registered in
  `apps/cli/src/cli/main.py:77–102`.
- **Behavior:** writes Claude Code hook entries (project
  `.claude/settings.json`, with `--global` opt-out):
  - `PostToolUse` on Edit/Write → `context-router update-index --file <path>`
    (debounced; reuses watcher's per-file path, 300ms debounce logic from
    `watcher.py:27`)
  - plus the SessionEnd hook from Phase C (one installer, both hooks)
- **Must be idempotent**, must not clobber existing user hooks (merge, don't
  overwrite), `hooks uninstall` removes only our entries.
- **DoD sketch:** negative_case = running install twice produces identical
  settings file; uninstall restores pre-install file byte-for-byte minus our
  entries.

## Phase C — Auto-save observations + memory health

### C1. Auto-capture at session end
- Today: manual only (`save_observation` MCP / `memory capture` CLI →
  `apps/mcp-server/src/mcp_server/tools.py:817`,
  `apps/cli/src/cli/commands/memory.py:488`). MCP server has NO shutdown
  handler (`apps/mcp-server/src/mcp_server/main.py` — initialize only), so
  the server cannot self-save on disconnect. The reliable vehicle is the
  client hook.
- **Mechanism:** `hooks install` (B2) adds a Claude Code `SessionEnd`/`Stop`
  hook → `context-router memory capture --auto`.
- **`--auto` mode derives the observation locally, no LLM call:**
  - `files_touched` from `git diff --name-only` + `git diff --cached`
  - `task_type` + summary seeded from recent pack queries in `pack_cache`
    (migration 0012) + branch name + commit subjects this session
  - mark provenance `auto`; existing dup-guard (same task_type+summary
    skipped) prevents spam on idle sessions
- **Honesty constraint:** an auto summary is worse than a hand-written one.
  Spec must say: auto-capture is a *floor* (never end a session with zero
  record), not a replacement; agents are still instructed to call
  `save_observation` with a real summary, which supersedes the auto one
  (same-session auto entry gets replaced, not duplicated).
- **DoD sketch:** outcome = a session that edits files and ends without
  manual save still yields one observation with correct files_touched;
  negative_case = session with no file changes and no packs writes nothing
  and logs `info: nothing to capture`.

### C2. Memory health check (answers "is the agent storing observations properly?")
- **Where:** extend `doctor` (`apps/cli/src/cli/commands/doctor.py`) with a
  memory section — pulls the `memory health` idea forward from the v5 vision
  in `docs/roadmap.md`, minimal version:
  - observation count + days since last observation
  - last-observation date vs last-commit date (committing code but not
    memory → WARN "agent is not saving observations")
  - provenance mix (how many still `branch_local` i.e. never committed)
  - orphaned `files_touched` (paths that no longer exist) ratio
- Output in both text and `--json` (closes backlog B3 for the memory
  section); exit 1 on WARN like existing doctor checks.
- **DoD sketch:** negative_case = repo with 10 commits since last observation
  WARNs with a named reason; repo with fresh observation passes.

## Phase D — Local savings dashboard

### D1. Pack-event telemetry (prerequisite)
- **New table** `pack_events` (migration): `ts, mode, query_hash, pack_tokens,
  baseline_est_tokens, item_count, memory_tokens, repo`. Written on every
  pack (CLI + MCP) in the same transaction that caches the pack.
  `baseline_est_tokens` = sum of full-file token estimates for selected
  items' files — the same conservative basis as the pydantic report, and it
  must be documented as an *estimate* in the UI.
- Privacy: store query *hash* + first 80 chars only; local-only DB, nothing
  leaves the machine. No network calls ever.

### D2. `context-router dashboard`
- **New command** `apps/cli/src/cli/commands/dashboard.py`; stdlib
  `http.server` only — CLI currently has zero HTTP deps
  (typer/pydantic/yaml/rich/cachetools/tree-sitter/watchdog) and the
  "minimal shipped surface" standard says keep it that way. Single
  self-contained HTML page (inline JS, no CDN) — same pattern as the existing
  `graph` D3 HTML export.
- **Shows:** total tokens saved (sum baseline − pack), savings %, packs/day
  bar chart, per-mode breakdown, memory-hit rate, last-7-days table.
  Default `localhost:7878`, `--port` flag, prints URL and stays foreground
  (Ctrl-C to stop).
- **DoD sketch:** outcome = after ≥1 pack, dashboard shows ≥1 event with
  nonzero savings; negative_case = empty DB renders "no pack events yet —
  run context-router pack" instead of a blank page; bind 127.0.0.1 only.

## Sequencing & release shape

```
A (accuracy)  ──►  B (auto-fresh)  ──►  C (auto-save + health)  ──►  D (dashboard)
   1 wk              1 wk                  1 wk                        1 wk
```

- A before B: don't automate refresh of a graph that miscounts (user call:
  "before that, is our graph accurate?").
- B before C: hooks installer (B2) is shared infrastructure for C1.
- D is independent of C and can run in parallel with it if needed.
- Suggested split if scope pressure appears: ship A+B as **v4.6.0**
  (correctness + auto-fresh), C+D as **v4.7.0** ("visible memory"). Decide at
  the end of Phase B.

**Ship gate:** `scripts/smoke-v4.6.sh` covering: duplicate-edge query returns
0; pack after edit shows fresh symbol; hooks install/uninstall idempotency;
auto-capture floor; doctor memory WARN path; dashboard on empty + non-empty
DB. Real-world re-validation on the pydantic clone (still on disk at
`~/Documents/project_context/realworld-test/pydantic`) to confirm rank ≤ 3
holds after A1/A2 ranking changes.

## Risks
- **A2 symbol-ID churn** invalidates cached packs/references → migration note
  + cache version bump.
- **B1 pack latency** — staleness scan must stay O(changed files); cap inline
  re-index at N=25 files with WARN fallback.
- **C1 auto-summaries pollute memory** — dup-guard + `auto` provenance +
  doctor surfacing the auto/manual ratio keep this honest.
- **D scope creep** — dashboard is read-only v1; no auth, no remote, no live
  websocket. Refresh = reload.
